# 双重拦截器问题修复 ✅

## 问题

登录 API 路径错误：
```
❌ POST /api/v2/144b73d9/admin/passport/auth/login
```

应该是：
```
✅ POST /api/v2/passport/auth/login
```

## 根本原因

有**两个地方**在修改 API URL，导致路径被修改了两次：

1. **`client.ts`** - 我们新添加的拦截器（正确的）
2. **`main.ts`** - 旧的拦截器（冲突的）

### 执行流程

```
原始 URL: /v2/passport/auth/login
    ↓
client.ts 拦截器: 检查不是 passport，跳过 ✓
    ↓
main.ts 拦截器: 添加 secure_path → /v2/admin/passport/auth/login ✗
    ↓
再次经过 client.ts: 不是 passport 开头，添加 144b73d9 → /v2/144b73d9/admin/passport/auth/login ✗✗
```

结果：URL 被错误地修改了！

## 解决方案

删除 `main.ts` 中的旧拦截器，只保留 `client.ts` 中的新拦截器。

### 修改的文件

**文件**: `xboard-frontend/packages/admin/src/main.ts`

**删除了**:
- 从后端获取 secure_path 的代码
- 添加拦截器的代码
- 不需要的导入

**保留了**:
- 基本的应用初始化
- Pinia、Router、ElementPlus、i18n 配置

## 现在的架构

### 单一拦截器（client.ts）

```typescript
// 只在 client.ts 中有一个拦截器
if (config.url && config.url.startsWith('/v2/') && !config.url.startsWith('/v2/passport')) {
  const securePath = import.meta.env.VITE_SECURE_PATH || '144b73d9';
  config.url = config.url.replace('/v2/', `/v2/${securePath}/`);
}
```

### 配置来源

secure_path 从环境变量读取：
- 开发环境: `xboard-frontend/packages/admin/.env.local`
- 生产环境: 构建时的环境变量

## API 路径对照表（最终版）

| API 类型 | 前端调用 | 实际请求 | 说明 |
|---------|---------|---------|------|
| 登录 | `/v2/passport/auth/login` | `/v2/passport/auth/login` | ✅ 不修改 |
| 登出 | `/v2/passport/auth/logout` | `/v2/passport/auth/logout` | ✅ 不修改 |
| 用户信息 | `/v2/user/info` | `/v2/144b73d9/user/info` | ✅ 添加 secure_path |
| 统计数据 | `/v2/admin/stat/getOverride` | `/v2/144b73d9/admin/stat/getOverride` | ✅ 添加 secure_path |
| 用户列表 | `/v2/admin/user/fetch` | `/v2/144b73d9/admin/user/fetch` | ✅ 添加 secure_path |

## 需要重启

修改了 `main.ts`，必须重启前端：

```bash
cd xboard-frontend
# Ctrl+C 停止
npm run dev:admin
```

## 验证

重启后，浏览器控制台应该显示：

```
✅ POST /api/v2/passport/auth/login - 200 OK
✅ GET /api/v2/144b73d9/admin/stat/getOverride - 200 OK
```

不应该再看到：
```
❌ [Admin] Loaded secure_path: admin
❌ [Admin] Secure path interceptor configured for: admin
```

## 为什么之前有两个拦截器？

`main.ts` 中的拦截器是旧的实现方式：
- 从后端 API 获取 secure_path
- 在运行时动态添加拦截器

新的实现方式（`client.ts`）：
- 从环境变量读取 secure_path
- 在初始化时就配置好
- 更简单、更可靠
