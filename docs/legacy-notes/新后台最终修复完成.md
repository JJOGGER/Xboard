## 修复的问题

## 修改的文件

### 1. API 客户端 - 自动添加 secure_path

**文件**: `xboard-frontend/packages/shared/src/api/client.ts`

```typescript
// 只对非 passport 的 V2 API 添加 secure_path
if (config.url && config.url.startsWith('/v2/') && !config.url.startsWith('/v2/passport')) {
  const securePath = import.meta.env.VITE_SECURE_PATH || '144b73d9';
  config.url = config.url.replace('/v2/', `/v2/${securePath}/`);
}
```

### 2. 环境变量配置

**文件**: `xboard-frontend/packages/admin/.env.local`

```env
VITE_SECURE_PATH=144b73d9
```

### 3. CORS 配置

**文件**: `config/cors.php`

```php
'allowed_origins' => [
    'http://localhost:5173',  // User frontend
    'http://localhost:5174',  // Admin frontend
    'http://127.0.0.1:5173',
    'http://127.0.0.1:5174',
],
'supports_credentials' => true,
```

## 常见问题

### Q: 还是报 404 错误？

**A**: 确保：
1. 后端已重启（CORS 配置生效）
2. 前端已重启（代码更改生效）
3. `.env.local` 中的 `VITE_SECURE_PATH` 与后端一致

### Q: 还是报 CORS 错误？

**A**: 确保：
1. 后端已重启
2. `config/cors.php` 中包含 `http://localhost:5174`
3. `supports_credentials` 设置为 `true`

### Q: 登录 API 还是被加了 secure_path？

**A**: 确保：
1. 前端已重启
2. 清除浏览器缓存（Ctrl+Shift+R）
3. 检查 `xboard-frontend/packages/shared/src/api/client.ts` 的修改是否正确

### Q: 如何查看后端的 secure_path？

**A**: 
```bash
# 方法 1: 查看 .env 文件
grep SECURE_PATH .env

# 方法 2: 使用 tinker
php artisan tinker
>>> admin_setting('secure_path')
```
