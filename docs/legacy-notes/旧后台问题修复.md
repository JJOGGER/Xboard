# 旧后台登录问题修复

## 问题描述

旧后台登录时报错：
```
{"message": "The route api/v2/passport/auth/login could not be found."}
```

## 问题原因

在配置新后台时，错误地修改了 V2 API 路由文件，给 Passport 和 User 路由添加了 `secure_path` 前缀：

### 错误的修改

**文件**: `app/Http/Routes/V2/PassportRoute.php`
```php
// 错误：添加了 secure_path 前缀
$router->group([
    'prefix' => admin_setting('secure_path', ...),
], function ($router) {
    $router->group([
        'prefix' => 'passport'
    ], function ($router) {
        // 路由变成了 /api/v2/144b73d9/passport/auth/login
    });
});
```

这导致路由从 `/api/v2/passport/auth/login` 变成了 `/api/v2/144b73d9/passport/auth/login`，旧后台无法访问。

## 解决方案

回滚了以下文件的修改：
1. `app/Http/Routes/V2/PassportRoute.php`
2. `app/Http/Routes/V2/UserRoute.php`  
3. `app/Http/Routes/V2/AdminRoute.php`

### 正确的路由结构

```
/api/v2/passport/*           - 公开路由（登录、注册等）
/api/v2/user/*               - 用户路由（需要登录）
/api/v2/{secure_path}/*      - 管理员路由（需要管理员权限）
```

## 验证

```bash
# 检查路由
php artisan route:list | grep "passport/auth/login"

# 应该看到：
# POST api/v2/passport/auth/login
```

## 修复后的状态

✅ 旧后台可以正常登录  
✅ 新后台不受影响（只修改了前端路由配置）  
✅ API 路由保持原样

## 教训

**重要**: 新后台的配置只应该修改：
1. 前端代码（`xboard-frontend/`）
2. Web 路由（`routes/web.php` - 只添加新路由）
3. 视图文件（`resources/views/admin-v2.blade.php`）

**不应该修改**:
- API 路由文件（`app/Http/Routes/V2/*.php`）
- 控制器
- 中间件
- 任何后端逻辑

新后台和旧后台共享相同的 API，不需要修改 API 路由！
