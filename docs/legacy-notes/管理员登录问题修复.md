# 管理员登录问题修复

## 问题描述

登录成功但没有跳转到仪表盘，停留在登录页面。

## 根本原因

1. **is_admin 字段获取问题**: 
   - 登录 API (`/api/v2/passport/auth/login`) 返回 `is_admin` 字段在响应的 `data` 中
   - 但前端代码从 `/v2/user/info` 接口获取用户信息，该接口不返回 `is_admin` 字段
   - 导致路由守卫检查 `is_admin` 时为 `false`，阻止访问仪表盘

2. **浏览器缓存问题**:
   - 之前修改了 `vite.config.ts` 和 `router/index.ts` 的 base path
   - 浏览器缓存了旧的路径配置（`/admin-v2/`）
   - 导致普通模式无法访问，只能在无痕模式访问

## 解决方案

### 1. 修复 is_admin 字段获取

**修改文件**: `xboard-frontend/packages/shared/src/types/auth.ts`

```typescript
export interface AuthResponse {
  token?: string;
  auth_data?: string;  // Backend returns 'auth_data' with Bearer token
  user?: AuthUser;
  is_admin?: boolean;  // Backend returns is_admin in login response
}
```

**修改文件**: `xboard-frontend/packages/admin/src/stores/auth.ts`

```typescript
const login = async (credentials: LoginCredentials): Promise<void> => {
  try {
    console.log('[Auth Store] Starting login...')
    const response = await authService.adminLogin(credentials)
    console.log('[Auth Store] Login response:', response)
    
    // Backend returns 'auth_data' with Bearer token
    const authToken = response.auth_data || response.token
    const cleanToken = authToken ? authToken.replace(/^Bearer\s+/i, '') : ''
    
    console.log('[Auth Store] Token extracted:', cleanToken ? 'Yes' : 'No')
    
    // Store token
    token.value = cleanToken
    authService.setToken(cleanToken)
    
    // Store user type
    localStorage.setItem('user_type', 'admin')
    
    // Get is_admin from login response directly
    // Backend returns is_admin in the login response data
    const isAdminFromResponse = response.is_admin ?? false
    console.log('[Auth Store] is_admin from login response:', isAdminFromResponse)
    
    console.log('[Auth Store] Fetching user info...')
    // Fetch user data after successful login
    await fetchUser()
    
    // Override is_admin from login response since /v2/user/info doesn't return it
    if (user.value) {
      user.value.is_admin = isAdminFromResponse
    }
    
    console.log('[Auth Store] User info fetched:', user.value)
    console.log('[Auth Store] Is admin:', isAdmin.value)
  } catch (error) {
    console.error('[Auth Store] Login error:', error)
    // Clear any partial state
    clearAuth()
    throw error
  }
}
```

**关键改动**:
1. 从登录响应中直接获取 `is_admin` 字段
2. 在获取用户信息后，用登录响应的 `is_admin` 覆盖用户对象的 `is_admin` 字段
3. 不修改后端 `/v2/user/info` 接口（保持原项目逻辑不变）

### 2. 清除浏览器缓存

**方法 1: 强制刷新（推荐）**
- Windows/Linux: `Ctrl + Shift + R` 或 `Ctrl + F5`
- macOS: `Cmd + Shift + R`

**方法 2: 清除浏览器缓存**

Chrome/Edge:
1. 按 `F12` 打开开发者工具
2. 右键点击刷新按钮
3. 选择"清空缓存并硬性重新加载"

Firefox:
1. 按 `Ctrl + Shift + Delete` (Windows) 或 `Cmd + Shift + Delete` (macOS)
2. 选择"缓存"
3. 点击"立即清除"

Safari:
1. 按 `Cmd + Option + E` 清空缓存
2. 或者在"开发"菜单中选择"清空缓存"

**方法 3: 清除特定站点数据**

Chrome/Edge:
1. 打开 `chrome://settings/content/all` 或 `edge://settings/content/all`
2. 搜索 `localhost:5174`
3. 点击"清除数据"

Firefox:
1. 打开 `about:preferences#privacy`
2. 点击"管理数据"
3. 搜索 `localhost:5174`
4. 点击"移除所选"

## 注意事项

1. **不修改后端接口**: 保持原项目的 API 逻辑不变
2. **从登录响应获取 is_admin**: 直接使用登录 API 返回的 `is_admin` 字段
3. **清除缓存**: 每次修改 base path 后都需要清除浏览器缓存
4. **开发环境路径**: 开发环境使用 `/`，不要加 `/admin-v2/`
5. **生产环境路径**: 生产环境使用 `/admin-v2/`
